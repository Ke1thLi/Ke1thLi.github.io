3. 还原真实密钥

继续分析 sub_401069(Str, Str1)，发现它调用了 sub_401A70。

打开 sub_401A70 后，发现其中存在一段硬编码字符串：

1

DH~mqqvqxB^||zll@Jq~jkwpmvez{

进一步分析发现，程序对字符串中的每个字符执行 XOR 0x1F 操作。

XOR 异或运算具有可逆性：

$(a \oplus b) \oplus b = a$

因此，只需要再次使用 0x1F 对硬编码字符串进行异或，就可以还原出真实密钥。

使用 CyberChef 还原密钥

  1. 打开 CyberChef。

  2. 将硬编码字符串粘贴到左上角的 Input。

  3. 在左侧 Operations 中搜索 XOR，添加到 Recipe。

  4. 在 XOR 模块中将 Key 设置为 1F，格式选择 Hex。

  5. 查看右侧 Output。

得到真实密钥：

1

[Warnning]Access_Unauthorized

注意： 硬编码字符串末尾的 { 不能遗漏。原始记录中存在一个不带 { 的字符串版本，两者长度不同。只有包含末尾 { 的版本，按 0x1F 逐字节异或后才能得到上述完整密钥。实际复现时，应以 IDA 中提取的字符串及程序使用的处理长度为准。

从函数的调用结构来看，它符合 RC4 加解密流程的典型特征。结合相关函数的具体实现，可以进一步确认是否存在状态数组初始化、密钥调度、伪随机密钥流生成和逐字节 XOR 操作。

RC4 的核心过程如下。

4.1 KSA：密钥调度算法

KSA（Key Scheduling Algorithm）负责初始化和置换状态数组。

标准 RC4 使用 256 字节的状态数组 S，初始状态为：

$S[i]=i, \quad 0 \le i < 256$

随后根据密钥内容对状态数组进行置换。

4.2 PRGA：伪随机生成算法

PRGA（Pseudo-Random Generation Algorithm）根据状态数组生成密钥流。每轮更新索引、交换状态元素，再根据状态数组计算当前密钥流字节。

4.3 XOR：加解密过程

RC4 将密钥流与数据逐字节异或：

$C = P \oplus K$

解密时执行：

$P=C\oplus K$

其中：

  • (P)：明文。

  • (C)：密文。

  • (K)：RC4 生成的密钥流。

因为 XOR 具有可逆性，所以 RC4 的加密和解密使用相同的核心操作，只要密钥和初始状态一致，就能恢复原始数据。

4.4 建议重命名函数

为了方便后续分析，可以将相关函数重命名为：

5. 解法一：使用 CyberChef 解密

这是我原本采用的解法：先还原密钥，再使用 CyberChef 对 enflag.txt 进行 RC4 解密。

5.1 准备密文

打开 enflag.txt，观察到的内容是乱码：

1

脗?鯨6;Y棠轳?睎5

需要注意，这只是文本编辑器显示的结果。为了避免字符编码转换造成数据损失，建议直接在 CyberChef 中加载原始文件，而不是简单地复制乱码。

如果使用十六进制数据作为输入，应确保它是原始文件字节的十六进制表示。

5.2 配置 RC4

  1. 清空之前的 Input 和 Recipe。

  2. 将 enflag.txt 加载到 Input。

  3. 搜索并添加 RC4 操作，不要选择 RC4 Drop。

  4. 将 Passphrase 设置为：

    1

    [Warnning]Access_Unauthorized

  5. 密钥格式选择 UTF8。

  6. 根据实际输入的数据形式选择输入格式：原始文件字节与十六进制文本的配置不能混用。

  7. 执行操作，检查解密结果。

输出格式应根据解密后的数据决定。对于包含任意二进制字节的输出，应优先保留原始字节，避免错误的 UTF-8 解码导致报错。

5.3 查看 Flag

按照上述流程解密后，预期得到：

1

flag{RC4&->ENc0d3F1le}

如果实际输出与预期不一致，应优先检查密钥长度、密文原始字节、输入格式和 RC4 配置。

6. 解法二：利用原程序完成解密

除了使用 CyberChef，也可以尝试复用题目程序本身的文件处理逻辑。

从 main_0 可以看出，程序选择选项 1 时，会以只读方式打开 flag.txt，并以写入方式打开 enflag.txt，随后调用文件处理函数。

这意味着程序会将 flag.txt 作为输入，将 enflag.txt 作为输出。若相关函数确实使用标准 RC4 处理数据，就可以通过准备输入文件来复用程序的处理逻辑。

6.1 操作步骤

  1. 备份原始密文。 先复制一份 enflag.txt，防止程序覆盖原文件。

  2. 准备输入文件。 将原始密文的原始字节写入 flag.txt，而不是将乱码文本重新编码后写入。

  3. 确认运行环境。 在隔离的虚拟机或专用分析环境中运行程序，不要直接在日常使用的主机上执行未知样本。

  4. 输入选项 **1**。 根据程序提示输入还原出的密钥。

  5. 检查输出文件。 如果程序执行成功，检查 enflag.txt 是否变成预期的明文内容。

需要说明的是，这种方法能否直接成功，取决于程序是否接受该密钥、实际使用的 RC4 状态是否一致，以及文件处理函数是否与当前分析一致。上述步骤应通过实际运行验证，不应仅凭反编译函数的名称认定成功。

7. 总结

本题主要涉及以下知识点：

  1. IDA 静态分析： 从 main 追踪到 main_0，再沿函数调用关系分析关键逻辑。

  2. XOR 异或： 利用异或运算的可逆性还原混淆后的密钥。

  3. RC4 算法： 通过 KSA、PRGA 和逐字节 XOR 理解文件加解密流程。

  4. CyberChef： 使用可视化操作验证密钥还原和 RC4 解密结果。

  5. 文件读写分析： 通过 fopen 的模式和函数参数确定输入输出文件。

  6. 程序复用： 在明确程序逻辑的前提下，尝试利用原程序的处理流程完成解密。

本题可以先通过 IDA 分析密钥和加密算法，再使用 CyberChef 验证解密结果。如果希望进一步理解 RC4，也可以自行编写 Python 解密脚本，或者在隔离环境中尝试复用原程序。
